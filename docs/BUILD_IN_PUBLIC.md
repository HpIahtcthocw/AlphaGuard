# Build in Public 计划

## 对外叙事

PIO 的传播点不是“AI 猜股票”，而是：

> 一个不允许你轻易被自己的回测骗到的个人投资操作系统。

适合持续公开的主题：

- 为什么 LLM 不能直接下单；
- 为什么每个策略必须先和三个简单基线比较；
- 如何标记实时、延迟、快照和合成数据；
- 一笔订单如何经过意图、风控、批准、报价和经纪商；
- 我们主动删除了哪些虚假的漂亮指标；
- 策略为什么会被暂停、淘汰或拒绝进入实盘。

## 发布节奏

1. 每周一篇工程日志：一个真实问题、失败尝试、修复和可复现实验。
2. 每两周一个带版本号的演示：必须附测试数、已知限制和下一验收门槛。
3. 每个研究结论附数据类型标签：`REAL`、`DELAYED`、`SNAPSHOT` 或 `SYNTHETIC`。
4. Roadmap 按验收条件关闭，不按“完成了多少页面”关闭。

## GitHub 增长结构

- `good first issue`：券商 CSV 映射、指标测试、文档翻译和样例数据。
- `research validation`：交易日历、公司行动、压力场景和参数稳定性。
- `broker adapters`：只接受具备幂等、回报同步、杀开关和审计的实现。
- `data providers`：必须说明许可、延迟、限流、字段语义和降级策略。

## 绝不使用的宣传

- 稳定 Alpha、稳赚、AI 预测股价；
- 已经是无人值守实盘或成熟机构平台；
- 把账户快照称为实时行情；
- 把哈希链称为绝对不可篡改或区块链；
- 用合成演示数据展示未经标注的收益率。

衡量项目影响力的核心指标不是 Star，而是：可复现实验数量、被测试捕获的研究错误、连续纸面运行天数、对账差异和外部贡献者完成的适配器数量。
