# 行情与执行架构

## 行情分层

PIO 不把“能取到一个价格”当成实时行情。标准报价必须包含：标的、市场、币种、价格、买卖价、前收盘、市场时间戳、接收时间、来源、是否实时和缓存年龄。

| 层级 | 当前适配器 | 用途 | 能否用于外部下单 |
| --- | --- | --- | --- |
| 授权实时行情 | Alpaca IEX/SIP（美股）、TuShare `rt_k`（A 股） | 盘中观察、下单前价格检查 | 可以，仍需风控与批准 |
| 账户快照 | `portfolio-snapshot` | 离线展示、账户估值降级 | 不可以 |
| 合成数据 | 研究演示生成器 | 测试回测引擎 | 不可以 |

默认路由为 `US=alpaca,CN=tushare`。供应商未配置、限流或返回缺失标的时，API 会保留错误，并按请求设置决定是否使用账户快照降级。降级结果始终为 `is_realtime=false`。

## 执行模式

| `PIO_EXECUTION_ADAPTER` | 行为 |
| --- | --- |
| `local-paper` | 只在本地账本模拟成交，默认模式 |
| `alpaca-paper` | 向 Alpaca Paper 账户提交真实模拟订单 |
| `alpaca-live` | 向 Alpaca 实盘提交订单，需要额外环境解锁 |

外部订单提交必须同时满足：

1. 订单意图状态为 `APPROVED`。
2. 批准后组合快照没有变化。
3. 取得实时、非降级报价。
4. 实时报价与批准参考价偏离不超过阈值。
5. 请求输入精确短语 `SUBMIT {intent_id}`。
6. 实盘模式的 `PIO_LIVE_TRADING_UNLOCK` 精确等于 `I_ACCEPT_REAL_MONEY_RISK`。

经纪商接受订单后只记录为 `SUBMITTED`，不会猜测成交。后续必须通过券商订单/成交回报同步来更新 `PARTIALLY_FILLED`、`FILLED`、`CANCELLED` 或 `REJECTED`，这是下一阶段的关键工作。

当前已提供 `POST /api/order-intents/{id}/sync`：它查询 Alpaca 订单状态并写入 `broker_orders`，同时保留原始回报和审计事件。该接口不会把 `filled_qty` 或 `filled_avg_price` 自动写入现金/持仓账本；成交对账必须单独校验幂等、部分成交、手续费和公司行动。

## 市场规则门禁（v0.6）

`execution/market_rules.py` 为研究回测和执行前检查提供中美市场的最小共同规则：A 股默认 100 股整数手、默认不允许股票做空，并按主板 10%/科创或创业板 20%提供涨跌停近似；美股默认 1 股整数单位、价格限制为空，但做空仍需券商权限和实时借券库存。多空回测会返回 `blocked_trade_days` 与 `rule_warnings`。

这些规则用于暴露不可执行的研究假设，不代表交易所撮合、停牌、熔断、部分成交、公司行动或券商保证金引擎。

## 生产前必须补齐

- WebSocket 或轮询行情心跳、市场时钟和延迟告警。
- Alpaca 订单与成交回报同步、断线恢复和日终对账。
- A 股券商网关、板块级交易规则、停牌和印花税规则（当前仅有研究级最小规则）。
- 拆股、分红、退市和复权数据的一致性校验。
- 密钥托管、权限最小化、IP/设备控制和操作审计。

## 多空研究回测边界

`POST /api/research/backtest/long-short` 已提供研究级负仓位回测：包括借券费、保证金融资、维持保证金、每日亏损保护、强平近似、滑点、佣金和次日执行。该模型用于比较策略风险，不等价于任何券商的真实保证金算法。

在进入模拟盘前，必须替换或校准：券商保证金规则、可借券实时库存、借券费变动、涨跌停/熔断、停牌、部分成交、盘前盘后、公司行动和强制平仓顺序。没有这些数据时，空头只能作为研究信号，不应转换为外部订单。
