# 行情与执行架构

## 行情分层

PIO 不把“能取到一个价格”当成实时行情。标准报价必须包含：标的、市场、币种、价格、买卖价、前收盘、市场时间戳、接收时间、来源、是否实时和缓存年龄。

| 层级 | 当前适配器 | 用途 | 能否用于外部下单 |
| --- | --- | --- | --- |
| 授权实时行情 | Alpaca IEX/SIP（美股）、TuShare `rt_k`（A 股） | 盘中观察、下单前价格检查 | 可以，仍需风控与批准 |
| 账户快照 | `portfolio-snapshot` | 离线展示、账户估值降级 | 不可以 |
| 合成数据 | 研究演示生成器 | 测试回测引擎 | 不可以 |

默认路由为 `US=alpaca,CN=tushare`。供应商未配置、限流或返回缺失标的时，API 会保留错误，并按请求设置决定是否使用账户快照降级。降级结果始终为 `is_realtime=false`。

## 执行模式

| `PIO_EXECUTION_ADAPTER` | 行为 |
| --- | --- |
| `local-paper` | 只在本地账本模拟成交，默认模式 |
| `alpaca-paper` | 向 Alpaca Paper 账户提交真实模拟订单 |
| `alpaca-live` | 向 Alpaca 实盘提交订单，需要额外环境解锁 |

外部订单提交必须同时满足：

1. 订单意图状态为 `APPROVED`。
2. 批准后组合快照没有变化。
3. 取得实时、非降级报价。
4. 实时报价与批准参考价偏离不超过阈值。
5. 请求输入精确短语 `SUBMIT {intent_id}`。
6. 实盘模式的 `PIO_LIVE_TRADING_UNLOCK` 精确等于 `I_ACCEPT_REAL_MONEY_RISK`。

经纪商接受订单后只记录为 `SUBMITTED`，不会猜测成交。后续必须通过券商订单/成交回报同步来更新 `PARTIALLY_FILLED`、`FILLED`、`CANCELLED` 或 `REJECTED`，这是下一阶段的关键工作。

## 生产前必须补齐

- WebSocket 或轮询行情心跳、市场时钟和延迟告警。
- Alpaca 订单与成交回报同步、断线恢复和日终对账。
- A 股券商网关、100 股整数手、涨跌停、停牌和印花税规则。
- 拆股、分红、退市和复权数据的一致性校验。
- 密钥托管、权限最小化、IP/设备控制和操作审计。
