# Personal Investment OS：产品与技术方案

## 1. 执行摘要

Personal Investment OS（简称 PIO）是一个面向个人投资者的本地优先投资工作台，连接四个闭环：

`市场数据 -> 研究/特征 -> 回测/验证 -> 组合与风险 -> 交易计划/执行`

它不是“让大模型预测股价”的聊天机器人，也不是一开始就追求无人值守实盘的交易平台。核心价值是把个人投资决策变成一条可复现、可检查、可回滚的流程：每个观点都有来源，每个信号都有版本，每笔交易都有理由、风险和审批记录。

### 首版成功定义

- 能导入并校验 A 股/ETF 的日线、复权、公司行动和交易日数据。
- 能记录账户、持仓、现金、费用、分红和人工交易流水，并计算时间加权收益、资金加权收益、回撤、波动率、夏普、换手和基准差异。
- 能用同一份数据快照执行可复现回测，明确区分训练、验证、测试和真实前视区间。
- 能生成带证据、假设、仓位、止损/失效条件和风险检查结果的交易计划。
- 能在纸面交易中模拟订单生命周期；实盘只允许人工确认后由适配器执行。

## 2. 用户与核心场景

### 目标用户

首版只服务一个拥有 Python 基础、希望系统化管理个人投资的用户。默认市场为中国股票/ETF，默认时区为 `Asia/Shanghai`，默认账户为个人账户。

### 高频场景

1. **每日复盘**：查看组合、持仓变化、风险暴露、新闻/公告摘要和待处理信号。
2. **研究一个想法**：提出因子或规则，获得数据质量报告、回测结果、敏感性分析和失败原因。
3. **生成交易计划**：把研究结论转成目标仓位、价格区间、订单拆分、最大损失和失效条件。
4. **管理真实投资记录**：导入券商成交单，核对现金、费用、分红和公司行动。
5. **复盘策略与决策**：比较计划与实际执行，记录偏差和事后归因。

## 3. 明确不做的事

- 首版不做高频、期权、融资融券、做市、跨市场套利。
- 首版不支持无人工确认的自动实盘下单。
- 不把 LLM 输出当作行情事实、财务事实或收益承诺。
- 不把公开网页抓取作为唯一数据源，不把未经许可的付费数据写入仓库。
- 不在同一阶段同时支持 A 股、美股、加密货币和多币种税务规则。

## 5. 产品模块

### 5.1 数据层

- 数据源适配器：本地 CSV/Parquet、AKShare、TuShare（可选）、券商导出文件。
- 规范化：统一代码、交易所、交易日、复权方式、币种、价格精度和公司行动。
- 数据质量：缺失、重复、停牌、异常跳变、未来数据泄漏、时间戳和来源记录。
- 快照：策略每次运行绑定不可变数据快照、代码版本和参数。

### 5.2 研究层

- 因子与指标：收益、波动、动量、均线、成交量、估值和自定义特征。
- 假设登记：假设、经济直觉、适用范围、预期失效条件、数据需求。
- 实验：参数、训练/验证/测试区间、随机种子、成本模型、基准和结果。
- 结果：收益曲线、回撤、风险、换手、分层、敏感性、稳健性和失败日志。

### 5.3 组合与风险层

- 账户、现金、持仓、成本、订单、成交、费用、税费、分红和公司行动。
- 目标仓位、当前仓位、行业/标的集中度、现金比例、单日损失和组合回撤。
- 硬门禁：数据过期、超限仓位、超限回撤、流动性不足、价格异常、重复订单。

### 5.4 决策层

- 研究摘要：结论、证据、反证、置信度和未解决问题。
- 交易计划：方向、标的、目标权重、价格/数量、有效期、最大损失、失效条件。
- 审批：草稿 -> 风控检查 -> 人工确认 -> 模拟执行/实盘适配器 -> 成交回写。
- 复盘：计划与成交偏差、滑点、归因、复盘标签和后续动作。

### 5.5 展示层

首版不追求大而全的仪表盘，优先做五个工作区：今日、组合、研究、回测、交易计划。任何图表都必须能回到原始数据、计算口径和版本。

## 6. Agent 设计

Agent 是受约束的研究协作者，不是拥有资金权限的交易员。建议角色如下：

| Agent | 输入 | 输出 | 权限 |
| --- | --- | --- | --- |
| Data Steward | 数据源、校验规则 | 数据质量报告、异常清单 | 只读数据目录 |
| Researcher | 假设、数据快照 | 因子/策略实验草案 | 沙箱代码与实验目录 |
| Backtest Auditor | 回测结果、配置、快照 | 泄漏/成本/稳健性审计 | 只读实验目录 |
| Portfolio Analyst | 账户、持仓、风险参数 | 暴露和再平衡建议 | 只读组合数据 |
| News/Fundamental Analyst | 许可来源的公告、财报、新闻 | 带链接的摘要和证据表 | 只读检索 |
| Risk Officer | 交易计划、组合状态、门禁规则 | 通过/拒绝/需人工复核 | 可阻止，不可下单 |
| Execution Clerk | 已批准计划 | 模拟订单或待签名订单 | 不能改变计划，不能绕过审批 |

Agent 输出统一为结构化 JSON，并保留提示词版本、模型、工具调用、来源、时间、人工修改和审批记录。任何自然语言结论都必须区分“事实、推断、假设、未知”。

## 7. 技术架构建议

### 首选形态

模块化单体 + 本地任务队列，避免首版过早拆微服务。

```text
Web UI / CLI
     |
Application API
     |
Domain modules: data | research | portfolio | risk | orders | audit
     |
PostgreSQL/SQLite + Parquet data lake + object artifacts
     |
Connectors: market data | broker export | paper broker | LLM/tools
```

### 技术栈建议

- Python 3.12：研究、数据和领域逻辑。
- FastAPI：轻量 API；Pydantic：边界模型与配置校验。
- DuckDB + Parquet：本地分析和可移植数据快照。
- PostgreSQL：从单用户本地运行向多账户扩展时使用；SQLite 可作为最小部署选项。
- Polars/Pandas：表格处理；VectorBT 或自研薄适配层用于批量回测；QuantStats 用于绩效报告。
- React/TypeScript：可选 Web UI；首版也可先用 CLI + 简单 Web 页面。
- Prefect/内置任务表：定时数据同步和实验任务；不引入重量级编排平台。
- OpenTelemetry/结构化日志：记录数据、实验、Agent 和订单链路。

### 关键领域实体

`Instrument`、`PriceBar`、`CorporateAction`、`DataSnapshot`、`ResearchHypothesis`、`FeatureSet`、`ExperimentRun`、`StrategyVersion`、`Account`、`Position`、`CashLedger`、`OrderIntent`、`Order`、`Fill`、`RiskCheck`、`Approval`、`DecisionJournal`。

## 8. 数据与策略生命周期

1. 采集：抓取原始数据并保存来源、时间、响应摘要和许可标签。
2. 规范化：统一字段和公司行动，生成数据质量报告。
3. 快照：冻结研究所需的时间范围与版本。
4. 研究：登记假设，生成特征和策略版本。
5. 验证：严格时间切分、交易成本、滑点、停牌/涨跌停和容量约束。
6. 审计：检查前视偏差、幸存者偏差、重复试验和参数过拟合。
7. 纸面交易：按真实市场时序运行，记录信号、订单、成交和异常。
8. 人工批准：风险门禁全部通过后生成待确认计划。
9. 执行与回写：适配器执行，成交结果回写到账本并触发复盘。

## 9. 关键非功能要求

- 可复现：同一快照、版本和参数应产生可解释的同等结果。
- 可审计：用户能回答“这个结论来自什么数据、哪个版本、哪次运行”。
- 可停止：一键停用所有自动任务和执行适配器。
- 可迁移：数据和交易流水可导出为标准 CSV/Parquet/JSON。
- 可隔离：Agent 沙箱不能访问密钥、券商账户或任意网络写权限。
- 可观察：数据同步、实验、风控和订单都有结构化状态与错误原因。

## 10. 主要风险

最危险的不是模型不够聪明，而是数据口径错误、回测幻觉、权限越界和用户误把建议当保证。项目必须把“拒绝交易”设计成正常结果，把不确定性和证据缺口展示出来，把所有高影响动作设为人工确认。
