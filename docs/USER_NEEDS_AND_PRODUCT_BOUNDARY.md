# 用户痛点与产品边界

## 1. 我们真正服务谁

### 不懂量化的个人投资者

这类用户并不需要先学会因子、优化器和机器学习。他们真正需要的是：知道自己持有什么、承担了什么风险、为什么要交易、结果是否优于简单持有，以及如何避免被情绪和回测幻觉误导。

### 有少量资金和研究能力的小型团队

小型机构通常没有完整的数据、研究、风控和运维团队。痛点不是缺少一个更复杂的模型，而是研究记录分散、数据口径不一致、策略难以复现、审批靠聊天、成交与组合无法及时核对。

首版以个人投资者为主，同时保证数据模型和审批流程未来可以扩展到 2–10 人的小团队。

## 2. 真实痛点优先级

| 优先级 | 痛点 | 系统应该怎样帮助 |
| --- | --- | --- |
| P0 | 不知道真实收益、成本和风险 | 建立可信账本，统一现金、持仓、分红、费用、基准和回撤口径 |
| P0 | 冲动交易、忘记当初理由 | 交易前写理由、风险、失效条件；交易后自动关联复盘 |
| P0 | 回测看起来很好但不可信 | 默认计入成本，检查未来数据、幸存者偏差、过拟合和不可成交情形 |
| P0 | 数据来源混乱 | 每个数字显示来源、更新时间和数据质量状态 |
| P1 | 信息过载 | 只展示需要判断的少量事项，区分事实、推断、假设和未知 |
| P1 | 不懂量化参数 | 用自然语言向导和安全默认值，复杂参数放在高级模式 |
| P1 | 组合偏离后不知道怎么调整 | 给出分步再平衡计划，而不是只给“买/卖”结论 |
| P1 | 小团队协作无法追责 | 研究、风控、批准、执行和人工修改全部留痕 |
| P2 | 想尝试 AI 但担心乱操作 | AI 只负责整理、质疑和生成草案，不能越过规则或直接下单 |

## 3. 非量化用户体验规则

1. 首页不展示模型名称和几十个指标，只回答“今天需要关注什么”。
2. 每个指标提供一句人话解释、正常区间和可能动作。
3. 每个策略同时展示收益、最大回撤、最差阶段、成本和与简单基线的差异。
4. 系统不使用“强烈买入”“必涨”“高胜率赚钱”等承诺式语言。
5. 默认只允许研究、模拟和计划；实盘执行必须单独开启。
6. 用户无需理解参数即可运行基线策略，但必须能查看系统用了哪些假设。
7. AI 输出必须能被用户追问：“证据是什么、什么情况下你会错？”

## 4. 能力边界

### 系统负责

- 数据收集、规范化、质量检查和版本记录。
- 资产账本、收益计算、风险暴露、基准比较和组合偏离提醒。
- 研究卡片、回测、稳健性检查、纸面交易和决策复盘。
- 把复杂结果解释为可确认的事实、风险和下一步。
- 通过确定性规则阻止超限、重复、过期和缺少批准的交易计划。

### 系统辅助但不替用户决定

- 提出研究假设、查找反证、解释指标、生成再平衡草案。
- 对公告、财报和新闻做带来源的摘要。
- 给出多个可选方案及其风险，而不是输出唯一答案。

### 系统明确不负责

- 预测短期涨跌或承诺收益。
- 代替持牌投资顾问、税务或法律专业人员。
- 在首版进行融资融券、期权、高频或无人值守实盘交易。
- 用大模型生成的数字替代市场数据、财务数据或成交数据。
- 因为一次回测优秀就自动把策略升级到真实资金。

## 5. Agent 边界

Agent 只能在工具白名单和结构化输出协议内工作。研究 Agent 可以提出假设；审计 Agent 可以拒绝不可信回测；风控 Agent 可以否决计划；执行组件只能接收已经批准且未过期的确定性订单意图。

以下能力永远不交给通用 Agent：账户密钥管理、风险上限修改、实盘开关、订单金额二次修改、审计日志删除。

## 6. 从优秀项目借鉴但不盲从

- 从 Portfolio Performance、Ghostfolio 和 Wealthfolio 借鉴“先把真实账本做好”。
- 从 Qlib、VectorBT 和 QuantStats 借鉴实验、批量验证和绩效分析。
- 从 Lean 和 vn.py 借鉴事件、订单、成交、费用和适配器边界。
- 从 TradingAgents、FinRobot 和 RD-Agent 借鉴多角色研究，但取消 Agent 的资金权限。
- 从 OpenBB 借鉴统一数据入口，但每个数据供应商仍需单独记录许可和质量。

我们不会直接复制某个项目的整套架构。GPL、AGPL、EPL 和自定义许可证的项目优先作为产品与交互参考；真正复用代码前必须进行依赖和分发方式评估。

## 7. 首个可交付闭环

首个闭环不是“跑出一个赚钱策略”，而是：

`导入示例/脱敏交易流水 -> 得到可信组合账本 -> 发现一项组合偏离 -> 生成带证据和风险的模拟再平衡计划 -> 人工确认 -> 写入模拟成交 -> 自动生成复盘记录`

完成这个闭环后，再加入策略研究和回测；纸面交易连续稳定运行后，才讨论有限实盘。

## 8. 判断项目是否走偏

如果出现以下情况，应停止新增功能并重新审视：

- 首页越来越像行情软件，却无法解释用户为什么要行动。
- Agent 说得越来越多，但来源、置信度和失败条件越来越少。
- 回测指标很多，却无法复现或没有真实交易成本。
- 还没完成对账和纸面交易，就开始接实盘券商。
- 用户必须先学习大量量化术语才能完成一次研究。
