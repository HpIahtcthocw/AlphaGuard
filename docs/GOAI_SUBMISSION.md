# Firebreak / GOAI 参赛提交包

## Competition Brief

| 项目 | 定义 |
| --- | --- |
| 作品名 | Firebreak / 个人投资研究与风险守门 Agent |
| 一句话 | 一个不负责荐股、专门阻止你被漂亮回测骗到的个人投资研究 Agent。 |
| 用户 | 做个人量化研究、但缺少机构级验证流程的个人投资者 |
| 单一任务 | 判断一条策略是否有资格进入模拟交易 |
| 核心噱头 | Agent 主动拒绝一笔“回测很好看，但证据不够可信”的交易 |
| AI 边界 | Qwen 理解任务、选择工具；确定性风险门禁保留最终否决权 |
| 安全边界 | 默认本地纸面盘，不承诺收益，不自动下单，不把合成数据冒充真实行情 |
| 当前分支 | `feat/goai-alpha-guard-agent` |

## 为什么符合赛道

Firebreak 不是在投资工作台上贴一个聊天框，而是完成一条可验证的 Agent 链路：理解目标、选择受限工具、调用真实回测、读取样本外证据、执行风险门禁、决定是否允许产生订单意图。它具有明确目标、工具使用、过程记忆（Trace）、环境反馈和安全约束。

评委在三分钟内能看到三个差异点：

1. Agent 的价值不是“能做”，而是有证据地说“不”。
2. Qwen 没有风险规则解释权，LLM 无法越权修改最终结论。
3. 页面提供数据指纹、回测指标、门禁明细和完整 Trace，数字可以复现。

## 黄金演示路径

### 0:00–0:25 问题

打开默认首屏，直接说：

> 个人量化最危险的时刻，不是策略亏了，而是回测太漂亮，让你误以为它已经可以交易。

页面任务已经填写：

> 验证低波动 ETF 轮动策略是否已经具备进入模拟交易的证据。

### 0:25–1:20 Agent 执行

点击“开始证据审计”。让评委看到工具 Trace 依次推进：

- `inspect_dataset`：检查数据来源、质量和指纹。
- `run_backtest`：运行策略和买入持有、月度等权、趋势过滤三条基线。
- `audit_backtest`：检查样本外表现和五段 Walk-forward。
- `apply_risk_gate`：由确定性代码做最终裁决。

配置 Key 时，Qwen 负责规划工具；未配置时必须指出页面显示的是“规则规划器演示（未调用 Qwen）”。

### 1:20–2:15 反转

页面落到：

> BLOCKED / 这笔交易，我拒绝执行。

固定演示会真实运行 1,100 个交易日，当前种子结果包括：

- 全样本年化收益约 2.23%，最大回撤约 -6.61%。
- 样本外年化收益约 4.64%，最大回撤约 -4.16%。
- 五段 Walk-forward 已完成。
- 结果仍然被拒绝，因为数据是 `SYNTHETIC_DEMO`，且缺少独立数据源核验、压力场景验证和至少四周模拟盘对账。

不要把这些数字描述为真实策略收益或未来预期。

### 2:15–3:00 闭环与安全

展开完整 Agent Trace，指出：

- 每个数字都来自现有回测引擎，不是 LLM 编造。
- 数据指纹让同一实验输入可以复现。
- 最后一步 `create_order_intent` 状态为 `SKIPPED`。
- 数据库没有新增订单意图，自动化测试锁死了这条边界。

收尾句：

> 好的金融 Agent，不只是替你寻找 Alpha，更要在证据不够时替你守住“不交易”的权利。

## 技术架构

```text
用户研究任务
    ↓
Qwen / 透明规则降级规划器
    ↓ 仅能选择白名单工具
数据来源检查 → 回测引擎 → 样本外与 Walk-forward 审计
    ↓
确定性风险门禁（LLM 不可覆盖）
    ├─ ELIGIBLE → 仍需人工批准
    └─ BLOCKED  → 不创建订单意图 + 输出证据 Trace
```

核心接口：`POST /api/goai/audit-demo`

核心模块：

- `agent/guardrail.py`：受控规划、工具白名单、风险门禁和证据聚合。
- `server/app.py`：真实回测演示和 Firebreak API。
- `alpha-guard.js`：执行状态、来源标识、证据与错误态。
- `tests/test_guardrail_agent.py`：越权、降级和合成数据阻断测试。

## 本地运行

```powershell
python -m pip install -e ".[dev]"
python -m uvicorn server.app:app --host 127.0.0.1 --port 4173
```

浏览器打开 `http://127.0.0.1:4173`。

Qwen 为可选配置：

```text
DASHSCOPE_API_KEY=
DASHSCOPE_MODEL=qwen-plus
```

Key 留空时，核心审计仍然可运行，但页面和 API 会明确披露没有调用 Qwen。

## 提交表单文案

### 作品简介（短版）

Firebreak 是一个个人投资研究与风险守门 Agent。它用 Qwen 理解研究任务并选择白名单工具，随后调用真实回测、样本外验证和 Walk-forward 审计；最终是否允许进入模拟交易，由 LLM 无法覆盖的确定性风险门禁裁决。黄金 Demo 中，策略回测看起来不错，但因为数据来源和生产验证证据不足，Agent 主动返回 `BLOCKED`，且不创建订单意图。它不荐股、不承诺收益，解决的是个人量化研究里“被漂亮回测骗到”的真实风险。

### 创新点（短版）

多数金融 Agent 展示“它能替你做什么”，Firebreak 展示“它为什么拒绝替你做”。Qwen 只有规划权，确定性代码保留 veto；每次结论附带数据指纹、真实工具输出、硬门禁和完整 Trace，既能解释，也能验证没有越权执行。

### 技术栈

FastAPI、Pydantic、pandas、NumPy、SQLite、原生 HTML/CSS/JavaScript、DashScope OpenAI-compatible API、Qwen Plus。

## 发布前验收

1. 清空 Key 运行一次，必须显示“未调用 Qwen”，并返回 `BLOCKED`。
2. 配置 Key 运行一次，必须显示实际模型名；Qwen 失败时必须透明降级。
3. 展开 Trace，确认原始证据可读，数据指纹不是空值。
4. 检查订单审计日志，确认 Demo 前后没有新建订单意图。
5. 桌面和手机各跑一次，按钮、指标和长指纹不能溢出。
6. 运行 `python -m pytest -q`，所有测试通过后再录屏。
