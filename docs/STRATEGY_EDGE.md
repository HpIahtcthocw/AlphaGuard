# 策略层：产品区分度与工程规范

## 1. 策略层的目标

我们的区分度不是“比别人多一个技术指标”，而是把策略变成普通投资者能理解、能质疑、能复现、能长期观察的产品对象。

每个策略必须回答五个问题：

1. 它利用的风险溢价或行为偏差是什么？
2. 它什么时候应该有效，什么时候应该失效？
3. 现实中如何成交，成本和容量如何处理？
4. 参数改变后结果是否仍然成立？
5. 用户如何知道系统是在执行规则，而不是临时生成故事？

## 2. 开源策略的使用分级

| 等级 | 典型来源 | 使用方式 | 是否可进入实盘候选 |
| --- | --- | --- | --- |
| A：可复用实现 | MIT/Apache/BSD，代码边界清晰且活跃 | 保留来源、版本、许可证和本地改动；写适配测试 | 可以，但仍需本项目审计 |
| B：研究参考 | Notebook、论文复现、教学仓库 | 只借鉴假设、特征和实验方法；自行重写生产逻辑 | 不可直接进入 |
| C：不可直接复用 | GPL/AGPL、许可证不明、数据依赖不清 | 只记录方法论，不复制代码和数据 | 不可直接进入 |
| D：自研策略 | 没有可靠开源实现或需要适配个人场景 | 先写研究卡片，再实现、回测、纸面观察 | 通过全部门禁后才可候选 |

当前核验的参考项目包括 Qlib（MIT）、Lean（Apache-2.0）、FinRL（MIT）、Machine Learning for Trading（MIT）、Zipline Reloaded（Apache-2.0）、bt（MIT）、AlphaLens（Apache-2.0）以及许可证限制更强的 Freqtrade Strategies、backtesting.py 等。项目活跃度只用于发现参考，不等于策略质量。

## 3. 首批策略组合

### S-001：ETF 防守型趋势轮动（自研）

- **目的**：在一组高流动性 ETF 中捕捉中期趋势；趋势不明确时保留现金。
- **信号**：月度调仓；使用上一个交易日收盘数据计算 126 日动量、20 日波动率和 200 日均线过滤。
- **选取**：只在价格高于 200 日均线且动量为正的候选中选动量最高者；最多持有 2 个，单标的上限 35%。
- **仓位**：按波动率倒数初步分配，再应用单项上限；组合目标年化波动率默认为 10%，不足以交易时留在现金。
- **执行**：信号日之后的下一个可交易日执行；交易成本、滑点和最小交易单位必须进入回测。
- **失效条件**：连续 3 次调仓后仍跑输等权基线、容量不足、数据质量异常，或纸面交易出现系统性成交偏差。
- **不声称**：不声称预测价格、不保证收益、不声称适用于单只股票或所有市场状态。

这不是“神奇策略”，而是一条可解释、低频、适合小资金验证的基线。它的价值在于让系统先拥有一条严格可审计的策略流水线。

### S-002：等权/固定比例基线（开源思想，自实现）

所有策略都必须与简单基线比较。首版使用等权持有和固定比例再平衡，不依赖复杂模型。若复杂策略不能稳定改善回撤、成本后收益或风险暴露，就不应进入候选池。

### S-003：市场状态驱动多空突破（研究版）

- **状态**：`signal-only`，当前只生成结构化多空候选，不进入组合回测或订单执行。
- **因子**：市场趋势状态、20 日收益、5 日量比、252 日突破、20 日有效突破次数、20 日大涨/大跌事件、20/120 日回撤、上涨/下跌成交量比、MA7/30/60 距离和首次支撑跌破次数。
- **做多**：Bull 状态下，极强上涨、放量、重复突破和低回撤条件共同形成候选评分。
- **做空**：Bear 状态下，持续下跌、重复跌破支撑和下跌量价确认形成候选评分；可借券、保证金和市场规则单独检查。
- **执行边界**：信号成立不等于可执行。A 股无券源时只能降低多头或使用对冲工具；美股也必须核验借券和保证金。
- **下一步**：加入真实涨跌停/借券/保证金模型后，才能进入多空回测。

### 横截面扫描与研究组合

`POST /api/research/signals/breakout/universe` 对股票池统一计算 S-003 因子，并返回多头/空头候选排名。研究组合使用显式的多头预算、空头预算和单标的上限；没有 `shortable=true` 的空头只会留在研究列表，不会进入可执行权重。输出中的 `gross_exposure` 和 `net_exposure` 是研究预算，不代表券商账户保证金可用额度。

- 横截面价值/质量/动量因子：需要可靠财务数据、行业中性和防幸存者偏差。
- 风险平价/波动率目标：需要稳定的相关性估计和极端行情测试。
- 宏观状态过滤：只有在数据定义和发布时间可审计时再做。
- 机器学习和强化学习：暂不作为首批生产策略，先作为研究沙箱，防止样本外失真和解释不足。

## 4. 策略准入门禁

策略必须依次通过：

1. 研究卡片完整，经济直觉和失效条件明确。
2. 数据快照、公司行动、交易日和许可证可追溯。
3. 回测严格按时间切分，信号与成交至少错开一个可交易日。
4. 交易成本、滑点、停牌、涨跌停、现金和容量已建模。
5. 与等权、买入持有和简单趋势基线比较。
6. 进行参数邻域、子区间、留出资产和压力场景测试。
7. 结果包含最差阶段、回撤恢复时间、换手和失败日志。
8. 至少连续 4 周纸面运行，成交偏差可解释。
9. 风控参数独立于策略参数，策略不能修改硬性风险上限。

## 5. 策略版本与淘汰

每次改变信号、成本、候选池或参数都生成新版本，不覆盖旧结果。策略状态只允许：`research -> backtest_passed -> paper -> candidate -> live_limited -> retired`。

淘汰条件包括：数据依赖失效、审计失败、连续观察期不符合预设风险边界、成本后优势消失、策略逻辑无法解释，或维护者无法说明最近的结果变化。淘汰是正常产品行为，不是失败。

## 6. Agent 在策略层的权限

- Researcher：可以提出假设和实验配置，不能修改风险上限。
- Backtest Auditor：可以标记失败、要求重跑，不能把失败改成通过。
- Risk Officer：可以拒绝计划，不能修改回测结果。
- Explanation Agent：只能读取结构化结果，不能创造不存在的收益数字或数据来源。

策略计算必须由确定性代码完成；大模型只做检索、解释、反证和研究编排。
